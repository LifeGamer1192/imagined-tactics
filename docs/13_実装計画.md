# 実装計画

ブラウザで動くヘックスのターン制戦術ゲームを作るための計画。この段階では実装しない。

**基本方針**：hist-sim の**任意の状態**（どのシナリオでも、どの年月でも、架空の大陸でも）を読み込み、そこからヘックスのゲームを始められるようにする。そのために、hist-sim のデータをゲームのデータに変える**変換ルール**を、例外なく機械的に決めておく。

- 勢力の数・顔ぶれは hist-sim の状態のまま。勢力を選び直したり置き換えたりしない。
- 武将の人数は hist-sim にいる人物のまま。人数の目安は設けず、**こちらで武将を自動生成しない**。
- 役職・兵種・軍略などの名前は、日本版の名称で書く（中国版は [00_固有名詞対応表.md](00_固有名詞対応表.md) を参照）。
- hist-sim・rts-mons は、同じ ccode フォルダにある兄弟プロジェクト。

---

## 全体像

```
hist-sim（任意の状態）
   │ hist-sim の「書き出し」ボタン（既存）→ .histsim ファイル
   │ または「この状態で hex で遊ぶ」ボタン（追加・任意）→ 直接受け渡し
   ▼
hex-sim：セーブの読み込み（P3）
   │ 変換ルール（P4、この計画の中心）
   ▼
hex-sim のゲーム開始データ（勢力・武将・兵・領・外交・戦場マップの素）
```

- hist-sim には、セーブをファイル（.histsim：gzip で圧縮した JSON）に書き出す機能が**すでにある**。hex-sim はそれをそのまま読めるので、hist-sim の改修なしで始められる。
- hist-sim のテスト用セーブ3つ（戦国1575年・ローマ前212年・架空の諸島30年）を試しに読み、変換に必要な項目がすべて揃っていることを確かめた（P3）。
- 妖は時代に合わせた兵種に、術は軍略に置き換えた（[14_兵種と軍略.md](14_兵種と軍略.md)）。
- 元の資料に由来する数値は、すべて1〜3%ずらしてある（20未満の小さな値は除く。14_兵種と軍略の5節）。

| P | 内容 | 主な流用元 | 前提となるP |
|---|---|---|---|
| P0 | 先に決めること | − | − |
| P1 | プロジェクトの土台 | hist-sim | P0 |

| P3 | hist-sim のセーブの読み込み | hist-sim（セーブ形式） | P1 |
| P4 | 変換ルールの実装（セーブ → ゲーム開始データ） | − | P2・P3 |
| P5 | ヘックス盤面と描画、戦場マップの生成 | hist-sim（カメラ） | P1・P4 |
| P6 | 移動 | hist-sim（移動範囲の計算） | P5 |
| P7 | 戦闘の計算 | rts-mons（能力補正）、dunmas-web（状態異常） | P2・P6 |

## P1　プロジェクトの土台

**目的**：ブラウザで動き、テストが回る空のプロジェクトを作る。

**作業**
1. hist-sim と同じ構成で作る（TypeScript ＋ Vite ＋ vitest）。node は兄弟フォルダの node-portable を使う。
2. hist-sim から次をコピーし、単独で動くようにする。
   - `src/core/rng.ts`（再現できる乱数）
   - `src/core/heap.ts`（優先度付きキュー）
   - `src/i18n/i18n.ts`（文字列の切り替え。日本版・中国版の名前の切り替えに使う）
   - `src/render/camera.ts`（スクロール・拡大縮小）
3. フォルダ構成

```
hex-sim/
  docs/            … 今の md 一式（00〜14 と 11_兵種能力値）をここへ移す
  data/system/     … P2 で作る仕組みのデータ（JSON）
  tools/           … 変換・検査スクリプト
  src/
    core/          … 乱数・キュー・ヘックス計算
    bridge/        … セーブの読み込みと検査（P3）
    convert/       … 変換ルール（P4）
    rules/         … 戦闘計算・移動・成長
    battle/        … 戦闘の進行
    ai/            … 敵の思考
    strategy/      … 戦略パート
    render/        … 描画
    ui/            … 画面部品
    i18n/          … 版の切り替え
  tests/
    fixtures/      … テスト用のセーブ（複数のシナリオ・年代）
```

4. `core` `bridge` `convert` `rules` `battle` `ai` は画面を一切参照しない、という決まりにする。テストと自動対戦を画面なしで回すため。

**完了条件**：`npm run dev` で画面が出て、`npm test` で乱数の決定性テストが通る。

| tactics.json | 軍略：消費・威力・射程・範囲・必中・効果・習得者 | 04 |

**完了条件**：検査が問題なしで終わる。件数が md と一致する。

## P3　hist-sim のセーブの読み込み

**目的**：hist-sim の任意の状態のセーブを、hex-sim で読めるようにする。

### 3-1　受け渡しの方式
| 方式 | 内容 | hist-sim の改修 | 使い勝手 |
|---|---|---|---|
| **A（最初に作る）** | hist-sim の既存の「書き出し」で保存した .histsim ファイルを、hex-sim で開く | 不要 | ファイルを1回選ぶ手間がある |
| **B（次に作る）** | hist-sim に「この状態で hex で遊ぶ」ボタンを足す。押すと hex-sim を新しいタブで開き、セーブをタブ間通信（postMessage）で直接渡す | ボタンと数行 | ワンクリック。別のアプリ（別オリジン）でも渡せる |
| C（任意） | 2つを同じオリジンで配信し、hex-sim から hist-sim のセーブ枠（自動・1〜5）を一覧して選ぶ | 配信の設定だけ | ファイル不要。ただし配信の形が縛られる |

推奨は、A → B の順。前回の計画にあった「中継ファイル（新しい書き出し形式）」の新設は、既存の書き出し機能があるので不要になった。

### 3-2　セーブの形式（実物で確認済み）
- .histsim ファイル＝gzip で圧縮した JSON。
- 中身は `{format: "hist-sim", version, savedAt, summary, world}`。型付き配列は `{__ta: 型名, b64: Base64}` の形で入っている。
- hist-sim の `tests/saves/` にある3つのセーブを試しに読んだ結果：

| セーブ | 年 | 存続勢力 | 領 | 存命人物 | 軍 | 武将候補の多い勢力 |
|---|---|---|---|---|---|---|
| 戦国 | 1575 | 57 | 81 | 131 | 63 | 織田家36、徳川家9、毛利家8、武田家7 |
| ローマ | 前212 | 18 | 70 | 95 | 23 | ローマ24、カルタゴ12 |
| 架空の諸島 | 31 | 9 | 86 | 110 | 25 | 最大19、最小10 |

（武将候補は、当主・世継ぎ・軍の将・存命の成人人物の延べ数。重複を除く前の数）

### 3-3　hex-sim 側の作業
1. **読み込み**（`src/bridge/histsim.ts`）
   - gzip の展開と、型付き配列の復元。hist-sim の `fromJSON` と `gunzip` は小さいので、hex-sim にコピーする。
   - 形式名（hist-sim）と版数を確認する。
   - 古いセーブにない項目を既定値で埋める。hist-sim の `restore()` が行っている補完（`??=` の部分）のうち、変換に使う項目と同じ扱いにする。
2. **型の共有**：hist-sim の型定義（`src/sim/types.ts` など）を、hex-sim から**型だけ**参照する（TypeScript のパス設定で `import type`）。実行時には hist-sim のコードを読み込まない。hist-sim 側で項目が変わったら、hex-sim のコンパイルが止まって気づける。
3. **読み出す項目**（世界の状態から使うもの。名前は hist-sim の `{ja, en}` のまま使う）

| 区分 | 項目 | hist-sim での出どころ |
|---|---|---|
| 基本 | 形式名・版数、書き出し元の hist-sim の版数、シナリオID（無ければ架空）、現在の年・月 | World.tick・startYear・scenario |
| 勢力 | 存続中の全勢力：名前・表記（label）・位（rank）・統治形態・経済・文化・宗教・色・首都・国庫・兵力の余力・技術・安定・正統性・威信・宗主国・従属の種類・特色（reforms） | World.nations |
| 当主まわり | 当主・世継ぎ・共同統治者：能力4つ・健康・特性・性別・生年・在位開始 | Nation.ruler・heir・coRuler |
| 人物 | 存命の記録上の人物：能力4つ・健康・特性・性別・生年・役割・名声・官職・仕えている勢力・生まれた家・在位歴・親・配偶者・関係（ties） | World.people（died が −1 のもの） |
| 軍 | 全軍：勢力・役割（守備・親衛・野戦・遊撃）・兵数・定数・士気・将・現在地・目標 | World.armies |
| 領 | 全領：名前・隣接・海路・持ち主・実際の支配者・文化・宗教・人口・繁栄・不穏・荒廃・城の強さ・建物・持ち主になった時期・主な地形（biome）・平均標高・大河の有無・通れるか・名産 | World.provinces・ps・seaLinks・goods |
| 外交 | 戦争（攻撃側・防衛側・開始時期・戦況）、同盟、停戦、勢力間の感情 | World.wars・alliances・truces・Nation.opinions |
| 戦場の素 | 各領のセルの地形（biome）・標高・川・位置。戦場マップの生成に使う | World.map・provinceOf |
| 記録 | 進行中の合戦、シナリオの記録上の合戦名（任意） | World.battles・battleStories |

**使わないもの**：年代記のログ、交易の履歴、乱数の状態、画面用のデータ。

4. **テスト用のセーブ**：hist-sim の `tests/saves/` の3つに加え、hist-sim で次の状態を書き出して `tests/fixtures/` に置く。
   - 戦国1560年・1582年、春秋戦国の前700年・前506年・前260年、架空の大陸の終盤
   - 小国だけの状態、人物がほとんどいない状態、戦争中の状態など、極端なもの

### 3-4　hist-sim 側の作業（方式Bのとき。hist-sim のフォルダで行う）
1. 画面に「この状態で hex で遊ぶ」ボタンを足す。
2. 押したら、今の状態のセーブ（既存の `snapshot()`）を作り、hex-sim を新しいタブで開いて、準備ができた合図を待ってから postMessage で渡す。
3. hex-sim の場所（URL）は hist-sim の設定に持たせる。

### 3-5　将来の発展（今回はやらない）
hex で戦った結果（領の持ち主の変化、武将の死去など）を hist-sim に戻し、歴史の続きを hist-sim で見る。hist-sim には「介入の記録」（journal）の仕組みがあるので、それに載せる形が考えられる。

**完了条件**：.histsim ファイルを hex-sim で開き、勢力・人物・領の件数と、年月を表示できる。テスト用の全セーブで読み込みが通る。

## P4　変換ルールの実装（セーブ → ゲーム開始データ）

**目的**：どんなセーブからでも、遊べる開始データを必ず作れるようにする。係数と対応表はすべて `convert.json` に出し、調整は JSON の書き換えで済むようにする。

### 4-1　勢力
- 存続している全勢力が、そのまま勢力になる。数の上限・下限は設けない。
- 名前は表記（label）を優先し、無ければ root を使う。
- 宗主国のある勢力は「従属」の状態で始まる（宗主国と同じ陣営として扱い、プレイヤーは選べる）。
- 兵糧（徴兵の資源）の初期値＝国庫 × 係数。毎ターンの収入は領から計算する（4-6）。

### 4-2　武将になる人物
次の人物を、仕えている勢力の武将にする。重複は人物IDで取り除く。

| 対象 | 条件 |
|---|---|
| 当主・世継ぎ・共同統治者 | 存続中の勢力のもの |
| 軍の将 | 全軍の将 |
| 記録上の人物 | 存命で、仕えている勢力が存続中のもの |
| 王族・一族 | 存命で、仕えている勢力が存続中のもののうち、15歳以上 |

- **15歳未満**は武将にしない。成長したら登場させる（P11）。
- **仕えている勢力が無い、または滅んだ**存命の人物は「浪人」にする。諸国巡りで登用できる（P11）。
- **武将が1人もいない勢力**は、当主だけで始まる。当主は必ずいる。

### 4-3　能力値の変換
hist-sim の能力4つ（政治・軍事・外交・魅力）は、記録上の人物も架空の人物も同じ0〜10の尺度なので、同じ式を使う。
記号：政＝政治、軍＝軍事、外＝外交、魅＝魅力、名＝名声（記録が無い人物は4）、健＝健康（0〜1）

| ゲームの能力 | 式 |
|---|---|
| 武力 | 35 + 5×軍 |
| 知略 | 35 + 2.5×(政 + 外) |
| 機敏 | 30 + 3×軍 + 2×魅 |
| 体力 | (250 + 10×軍 + 5×魅) × (0.7 + 0.3×健) |
| 法力 | 知略 × 0.8 |
| 采配力 | 80 + 20×魅 + 10×(名 − 4) |
| 采配範囲 | 2 ＋（魅7以上で+1）＋（魅9以上で+1）＋（カリスマで+1）、最大4 |

ここに、選ばれた役職の能力補正（01_汎用役職）を足したものが最終的な能力値になる。

**特性による補正**（hist-sim の23特性すべてに割り当てる）
| 特性 | 能力値への影響 | 効果（パッシブ扱い） |
|---|---|---|
| 勇敢 | 武力+3 | 反撃ダメージアップ |
| 臆病 | 武力−3、機敏+5 | 回避率アップ、撤退しやすい |
| 武人 | 武力+5 | 命中率アップ |
| 賢明 | 知略+5 | − |
| 学者 | 知略+5 | 獲得経験値+10% |
| 天才 | 知略+5 | 獲得経験値+20% |
| 愚か | 知略−5 | − |
| 病弱 | （健康で反映済み） | − |
| カリスマ | 采配力+40、采配範囲+1 | − |
| 酒好き | 機敏−3 | − |
| 疑り深い | − | 寝返り・謀略にかかりにくい |
| 敬虔 | − | 回復の軍略の効果+10% |
| 皮肉屋 | − | − |
| 残酷 | − | 会心率+5% |
| 公正・優しい・満足・寛大 | − | 忠誠が下がりにくい（戦略） |
| 強欲・野心 | − | 忠誠が下がりやすく、寝返りしやすい（戦略） |
| 築城家 | − | 城の守り+（戦略） |
| 改革者・統一者 | − | 内政の効果アップ（戦略） |

hist-sim では、天才・武人・カリスマの人物は元の能力値がすでに上がっている。上の補正はそれとは別に足す。

**成長の伸びやすさ**：能力ごとにS・A・B・Cを付け、レベルアップ時の上昇量に掛ける（S ×1.3、A ×1.15、B ×1.0、C ×0.85）。
- 武力は軍、知略は (政+外)÷2、機敏は (軍+魅)÷2 で決める
- 9以上がS、7以上がA、5以上がB、それ未満がC

**開始時のレベル**：3 + (名 − 4)×3 + 経験年数÷3（1〜25に収める）
- 経験年数 ＝ 年齢 − 20（0〜15に収める）。登場年の記録が無い人物にも使えるよう、年齢で数える。
- 在位中の当主は+3。

### 4-4　役割と初期の役職
**役割**は、記録上の人物ならその役割（将軍・大臣・学者・芸術家・聖人・英雄・探検家 など）を使う。記録が無い人物は、次の順で決める。
1. 当主・世継ぎ・共同統治者 → 「当主」
2. 軍の将 → 将軍
3. それ以外 → 能力4つのうち最も高いもので決める（軍 → 将軍、政 → 大臣、外 → 大臣、魅 → 英雄）。同点なら軍・政・外・魅の順。

**初期の役職**
1. 性別に合う下級役職それぞれの「適性スコア」を計算する。

| 役職（男） | 適性スコア | 役職（女） | 適性スコア |
|---|---|---|---|
| 足軽 | 軍 + 政/2 | 薙刀衆 | 軍 + 政/2 |
| 野武士 | 軍×1.2 ＋（勇敢か武人なら+2） | 弓女 | 軍 + 魅/2 |
| 乱波 | (軍+魅)/2 ＋（英雄か探検家なら+2） | 歩き巫女 | 魅 + 軍/2 ＋（英雄なら+2） |
| 僧兵 | 軍 ＋（敬虔なら+2） | 白拍子 | 魅 + 外/2 ＋（芸術家なら+3） |
| 軍配者 | 政 + 外 | 女軍配者 | 政 + 外 |
| 僧 | (政+外+魅)/2 ＋（敬虔なら+2）＋（聖人なら+3） | 尼 | (政+外+魅)/2 ＋（敬虔なら+2）＋（聖人なら+3） |

   役割による加点：将軍なら武の役職（足軽・野武士・僧兵・薙刀衆・弓女）に+2。大臣・学者なら軍略の役職（軍配者・僧・女軍配者・尼）に+2。
2. 能力値が役職の条件（01_汎用役職の下級条件）を満たすもののうち、スコアが最も高い役職にする。同点なら表の上にあるもの。
3. どれも条件を満たさなければ、スコア最高の役職にし、足りない能力値を条件ぎりぎりまで引き上げる。
4. 開始レベルが10以上なら上級、20以上なら最上級にする。熟練度は満たしたものとみなす。
   - 足軽 → 侍 か 剣士：機敏が68以上なら剣士
   - 侍 → 侍大将 か 外道武者：残酷・皮肉屋・野心のどれかがあれば外道武者
   - ほかの系統は分岐なし

### 4-5　当主の固有役職
当主（在位中の者）には、汎用役職の代わりに固有役職を付ける。勢力の統治形態・経済・当主の性別と年齢で、次の表の上から順に当てはまるものを使う。

| 条件 | 固有役職の系統（上級 → 最上級） |
|---|---|
| 統治形態が神権 | 門主 → 法王 |
| 経済が海洋 | 船大将 → 海賊衆総帥 |
| 統治形態が共和制で、当主が女性 | くノ一頭領 → 歩き巫女総帥 |
| 当主が女性 | 女城主 → 女大名 |
| 統治形態が部族・首長制 | 国人 → 国衆の雄 → 古強者 |
| 当主が25歳未満 | 若殿 → 天下人 |
| それ以外（君主制・帝国・共和制の男性） | 大名 → 大大名 |

- 最上級へは、開始レベル20以上、または領の数が全領の25%以上なら昇進済みで始める。
- 当主が代わったら、新しい当主にこの表を当て直す。
- 固有役職の能力補正は、同じ段階の汎用役職の平均に＋αとする（P2で決める）。
- 鉄砲・大筒・からくりの固有系統は当主用ではなく、勢力の特色に結びつける（4-8）。

### 4-11　変換の保証

2. **戦場マップの生成**：セーブの、その領のセルの地形・標高・川から作る。

|---|---|

## P7　戦闘の計算

**作業**
1. **能力補正の重ね掛け**：rts-mons の `applyEffects`（倍率 → 加算 → 上書きの順。効果は期限付き）を TypeScript に移植する。formation-breaker の `layers.ts` を型付きのお手本にする。

2. **1ターン＝1か月**：内政 → 移動・出陣 → 戦闘 → イベント の順。暦は hist-sim の年月の続き。
3. **兵糧**：領からの収入で、兵の徴兵と維持に使う。
4. **諸国巡り**：武将を派遣して、浪人の登用・品の入手・経験値。成功率は能力と名声で決める。
5. **人物の出入り**：15歳になった一族の登場、浪人の登用、寝返り（関係と忠誠から）、死去（年齢と健康から）。友が戦場で出会うと仕官する仕組みもここに入れる。
6. **当主の代替わり**：当主が死んだら世継ぎが継ぎ、固有役職を当て直す（4-5）。
7. **外交**：同盟・停戦・従属を、セーブの状態から続ける。
8. **勢力の思考**：攻める相手を、戦力比・感情・戦争状態で選ぶ。
9. **勝利条件**：全領の統一、または一定数の領の獲得。

**完了条件**：テスト用のセーブから始め、数か月進めて、侵攻 → 戦闘 → 領の獲得まで続けて遊べる。

## リスクと対策

| リスク | 対策 |
|---|---|
| hist-sim のセーブ形式が変わる | 読み込みで版数を確認し、無い項目は既定値で埋める。hist-sim の型を型だけ参照し、変更があればコンパイルで気づく |
| 人物がほとんどいない状態を読み込む | 当主は必ずいるので遊べる。武将が少ない勢力は兵の配備で戦う。人数を補う自動生成はしない |
| 勢力が非常に多い状態（数十） | 戦略マップの描画と勢力の思考を、勢力数に比例しない作りにする。テスト用のセーブに勢力の多い状態を入れる |
| 変換結果が時代によって偏る | 係数を convert.json に出し、P12の自動対戦で複数の時代を比べながら調整する |
| 技の効果の文章がデータにしにくい | P2で効果の書き方を先に決め、表せないものは一覧にして個別に実装する |
| 戦略パートの規模が大きい | P8（戦闘の試作）とP10（成長）で一度区切り、遊べる状態を先に作る |
| 流用コードの依存関係 | rts-mons のコードは全体のデータに依存しているので、移すときに引数で受け取る形に直す |
