# 公開の手引き

hex-sim をウェブに置いて、ほかの人が遊べるようにするための手順。2026-10-11 に、この PC で確かめたことだけを書いてある。確かめていないことは、最後の「確かめていないこと」にまとめた。

## 1. ビルドする

```powershell
cd C:\Users\guser\Desktop\ccode\hex-sim
$env:PATH = "..\node-portable\node-v22.23.2-win-x64;$env:PATH"
npm test           # テスト
npm run build      # 型チェックのあと、dist\ に出力する
```

`dist\` の中身が、公開するもののすべて。

| 中身 | 内容 | 大きさ |
|---|---|---|
| `index.html` | 画面と CSS | 約10KB |
| `assets\` | プログラム（1ファイル。仕組みのデータも入っている） | 約0.3MB |
| `art\` | 絵（地図の記号、地形、兵の駒、背景）。210枚 | 約1.5MB |
| `samples\` | サンプルのセーブ3つ（.histsim） | 約1.9MB |

合わせて約3.6MB。サーバー側のプログラムは要らない（ファイルを置くだけ）。`art-src\`（絵の元のシート）と `docs\` は `dist\` に入らない。

## 2. 置く

`dist\` の**中身**を、公開先のフォルダにそのまま置く。フォルダはどこでもよい。

- 例：`https://example.com/games/hex-sim/` で出すなら、サーバーの `games/hex-sim/` に `index.html`・`assets`・`art`・`samples` を置く。
- 読み込み先はすべて「このページからの相対」にしてある（`vite.config.ts` の `base: './'`）。置き場所に合わせてビルドし直す必要は無い。
- アドレスは、末尾に `/` を付けた形（`…/hex-sim/`）か、`…/hex-sim/index.html` で開く。

### 置く前に手元で確かめる

```powershell
npm run build
node tools/subdir-check.mjs
```

`dist\` を `http://127.0.0.1:5185/games/hex-sim/` として出す小さなサーバーを立て、ブラウザを自動で操作して「タイトル → 案内を開いて閉じる → サンプル → 戦闘開始 → 戦略 → 月を進める」まで進める。サブフォルダの外を読みに行っていないか、読み込みに失敗したものが無いかも見る。終わるとサーバーは自動で止まる。

確かめた結果：画面の流れはすべて通り、サブフォルダの外への読み込みは無かった。ただし、次の1つが残っている。

- **名所の絵が無い**：戦略マップが hist-sim の名所の絵（`art/map/wonder_…webp`）を読みに行くが、hex-sim の `public\art\map\` に入っていないので 404 になる。絵が出ないだけで、遊ぶのに支障は無い。開発サーバーでは気づかない（無いファイルにも画面の HTML を返すため）。直すなら、hist-sim の `public\art\map\wonder_*.webp`（31枚）を hex-sim の `public\art\map\` に写してビルドし直す。

## 3. hist-sim の「この状態で hex で遊ぶ」の行き先

hist-sim の「セーブとロード」にあるこのボタンは、hex-sim を新しいタブで開いて、いまの世界を渡す。開く先は hist-sim 側で決めている（`hist-sim\src\ui\hexLink.ts`）。

| 決め方 | 内容 |
|---|---|
| 既定の値 | `DEFAULT_URL`。いまは `http://localhost:5183/`（開発サーバー） |
| ブラウザごとの上書き | hist-sim のページの localStorage のキー `histsim.hexUrl`。値があれば、既定より先に使う |

**公開するときは、hist-sim 側の `DEFAULT_URL` を、hex-sim を置いたアドレス（末尾の `/` まで）に書き換えて、hist-sim をビルドし直す必要がある。** 書き換えないと、遊ぶ人のブラウザは `localhost:5183` を開こうとして、つながらない。

自分のブラウザだけで試すなら、hist-sim のページで F12 を押し、Console に次を入れる（消すときは `localStorage.removeItem('histsim.hexUrl')`）。

```js
localStorage.setItem('histsim.hexUrl', 'https://example.com/games/hex-sim/')
```

受け渡しの仕組み（コードを読んで確かめた）
- hex-sim は、開かれると、開いた元のページに「準備できた」と知らせる。hist-sim はそれを受けて世界を送る。15秒たっても知らせが来なければ、hist-sim の画面に、つながらなかった旨の知らせが出る。
- hist-sim と hex-sim のアドレスが別のドメインでも渡せる作りになっている。
- hex-sim 側は、送り主がどのページかを確かめていない。届いたものはセーブとして読めるかを調べてから使い、読めなければタイトルにエラーを出す。

このボタンを使わなくても、hist-sim で「書き出し」たファイル（.histsim）を、hex-sim のタイトルの「セーブファイルを選ぶ」で読み込めば同じことができる。

## 4. 絵の出どころと表記

- 地形、兵の駒、背景、橋・沼などの記号は、AI で生成した絵。元のシートは `art-src\` にある。
- 地図の記号（山・森・町）は、hist-sim の絵を写したもの（`public\art\map\`）。
- タイトル画面の下に「地図の記号、地形、兵の駒、背景の絵は AI で生成したものです。」と出している（`src\ui\app.ts` の `titleScreen`）。公開先で別の表記が要るなら、ここを直す。

## 5. セーブの保存場所

- 戦略のセーブは、遊ぶ人のブラウザの中（IndexedDB の `hex-sim` という入れ物）に入る。サーバーには何も送らない。
- ブラウザの保存場所は、アドレス（`https://example.com` の部分）ごとに分かれている。**公開先のドメインを変えると、前のアドレスで作ったセーブは見えなくなる。** ブラウザの閲覧データを消したときも消える。
- 別の端末や別のブラウザへ移すときは、戦略の画面の「セーブ」→「ファイルに書き出す」で .hexsim を作り、移した先のタイトルの「セーブファイルを選ぶ」で読み込む。
- おまかせの速さの設定だけは、localStorage（キー `hexsim.aiSpeed`）に入る。

## 6. 遊び方の案内

画面の右下の「？」で、遊び方の案内が開く（`src\ui\help.ts`）。数値は `data\system\` の JSON から作るので、調整してビルドし直せば案内も変わる。確かめ方は [16_試験手順.md](16_試験手順.md) の 9。

- 末尾の `/` を付けないアドレス（`…/hex-sim`）で開いたときの動き。サーバーが `/` 付きへ送り直す設定なら問題ないはずだが、試していない。
- hist-sim の `DEFAULT_URL` を本番のアドレスに変えての受け渡し（hist-sim 側は触っていない）。

## 公開のやり方（hist-sim と同じ方式、2026-10-11 に決定）

ソースは公開しない。ビルド結果だけを、公開用の別リポジトリ（public）に置いて GitHub Pages で配信する。hist-sim が `LifeGamer1192/imagined-chronicles` で行っているのと同じ。

- 公開物は `release/site/`：`dist/` の中身 ＋ `.nojekyll` ＋ 公開用の `README.md`。このフォルダ自体が git のリポジトリで、初回のコミットまで済んでいる。
- 初回：GitHub で空の公開リポジトリを作り、`release/site` で `git remote add origin https://github.com/LifeGamer1192/<名前>.git`、`git push -u origin main`。リポジトリの Settings → Pages で、Branch を `main`・`/ (root)` にする。
- 更新：`npm run build` → `dist/` の中身を `release/site/` に写す（`.git`・`.nojekyll`・`README.md` は残す）→ コミットして push。
- 公開したら、hist-sim の `src/ui/hexLink.ts` の `DEFAULT_URL` を公開先のアドレスにして、hist-sim を公開し直す。

## 見本のセーブを本物の地形で作り直した（2026-10-11）

- hist-sim のテスト用のセーブ（`hist-sim/tests/saves`）は、通信なしで作るので、地形が簡易な形になっている（陸は一律200m、日本は瀬戸内海も伊勢湾も無い丸い形）。これを見本に使っていたため、日本地図が丸く見えていた。
- 見本は、公開版の hist-sim で作り直す：`node tools/make-sample.mjs <シナリオ> <史実度> <止める年月> <出力> [種]`。公開版は実際の標高（Terrain Tiles）から地形を作るので、海岸線が本物になる。作ったセーブは `art-src/saves/` に置き、`public/samples/` と `tests/fixtures/` に写す。
  - 日本の戦国：`sengoku 5 1575:1`（種 HEXSK）。領は81から209に増えた。
  - 春秋戦国：`shunju 5 259bc:1`（種 HEXSJ）。
  - ローマ：`rome 3 212bc:1`（種 HEXRM）。
  - 架空の多島海は、もともと作られた地形なので、そのまま。
- 歴史の進み方は作り直すたびに少し変わる（例：春秋戦国の見本は、楚が大きい世界になった）。
- タイトルの表記に、地形の出どころ（Terrain Tiles、Natural Earth）を足した。

## 見本を作る道具を、hist-sim の until に替えた（2026-10-12）

- hist-sim に、アドレスの `until`（例：`until=1575:1`、`until=259bc:1`）で、その月まで最高速で進んでセーブを書き出す機能が入った（hist-sim の P116）。終わると `document.body.dataset.until` が `done` になる。
- `tools/make-sample.mjs` は、これを使う形に書き換えた。画面の速さのボタンや暦の文字を読む必要が無くなり、1つ6〜8秒で作れる（前は、日本の戦国で約20秒、春秋戦国で約1分）。
- 同じ種・同じ年月で作ったセーブは、今の見本と同じになることを確かめた（日本の戦国とローマで、暦・勢力の数・領の数・領の持ち主・地形が一致）。見本のファイルは入れ替えていない。
- これで、hist-sim の画面の部品（速さのボタン、暦の文字、セーブの画面）には頼らなくなった。頼っているのは、アドレスの引数 `seed`・`scn`・`fid`・`until` と、`dataset.until`・`dataset.untilFile` だけ。
